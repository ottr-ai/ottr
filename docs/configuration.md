A card that came from an existing pull request (a Dependabot update) never opens a second one: it adopts that PR and waits for GitHub to merge it — and a Dependabot card filed before the board tracked source PRs adopts the PR its prompt's head line names. Fixes beyond a Dependabot PR's head ship as a follow-up pull request: the board pushes the card branch, opens one PR against the Dependabot branch so the fixes land with the bump (against the target branch when the card branch cherry-picked or rebased the bump, so they land after the bump merges), and links it in one comment on the Dependabot PR; the card waits for both PRs to merge. Ottr never merges or closes the PR — humans merge under the repo's protection rules. When the card ends, the server deletes the card branch it pushed on origin (after the merge's done write, or on cancel — with an open PR, GitHub closes it when its head branch goes). Before each next ship action or PR metadata write, the server reads the current cancel and turn state. A completed cancel stops later ship actions and metadata writes, including a cancel that keeps the card at `needs_you`. It cannot undo a push or GitHub request that already started. The card also watches its open pull request: new review comments and changes-requested reviews park the card as needs you, with the feedback as untrusted data on the card. A reply starts a fix turn, and the fix push updates the same pull request. | Fork research | off | **Settings**, per project: hourly watch of the project's GitHub forks; findings arrive as proposals you accept. ## Remote access

Public hostnames need a login (first visit creates the admin user) or the API key from **Settings**. Loopback access needs no login. Costly routes on a public hostname (card creation, task turns, git and GitHub operations) carry a per-source limit of 60 requests in 10 minutes; over the limit the route answers `429` with `Retry-After` (specs/public-api-request-limit.md). Serve HTTPS with `tailscale serve --bg --https=443 http://127.0.0.1:4747`, set `OMP_TRACKER_PUBLIC_HOSTS`, and the board installs to a phone's home screen; Web Push (**Settings → Notifications**) then delivers alerts. It is the only OS notification channel: desktop browsers subscribe the same way as phones. Each device picks its classes (Request, Error, Complete), and project mutes apply to every device. Push pauses while a board tab is focused. When an alert's cause clears or you acknowledge it, Ottr retracts the notification, and a bell acknowledgement is shared by every device. **Settings → Session → Sign out everywhere** rotates the session secret and revokes all login sessions. **Settings → Session** lists the login sessions, marks the current browser, and can sign out a single session. Non-GET API requests must send an `Origin` header matching the board URL.

Field text uses 16px when the viewport is 720px wide or less, or when the primary pointer is coarse at any width. This includes landscape phones and the New task, settings, search and model controls. Fine-pointer desktop views keep their compact density above 720px. User zoom remains unrestricted.

## Card edit conflicts

Two browser tabs can edit one card at the same time. The card edit routes accept an optional `revision` field: the task text edit, the steer edit, the steer cancel, the model choice, the release notes edit, and the editor's hold claim (`/edit/start`). Send the `revision` value that the card carried when you loaded it. The write lands only when the card still carries that revision. A stale write answers `409`, and the body holds the card's current state, so your client can re-read and retry. A request without `revision` behaves as before. The hold claim and its release never move the revision: they are bookkeeping, not content. The board sends `revision` on every edit; on a `409` it keeps your text and shows the card's current version beside it.
